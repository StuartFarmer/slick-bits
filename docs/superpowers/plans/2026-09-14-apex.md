# APEX implementation plan

Implement the supplied *Automatic Engineering of Long Prompts* paper as a standalone
`apex/` project using the local Slick checkout. The supplied algorithm is the spec.

- [x] Add an assert-based offline check for sentence preservation, LinUCB against
  the primal ridge equations, signed history retrieval, parent-relative reward,
  beam retention, budgets, and Slick rendering/provider integration.
- [x] Implement `apex/apex.py`: immutable prompt fragments, normalized cached
  embeddings, ridge LinUCB, guided mutation, and immediate top-k beam updates.
- [x] Implement `apex/run.py`: offline demo, local T5 encoding, Slick providers,
  JSON/JSONL datasets, disjoint training/test evaluation, and saved artifacts.
- [x] Add requirements and usage documentation, then run the checks and demo.

Defaults: beam 4, alpha .05, random-arm probability .5, four history examples
with strict normalized Euclidean distance < .5, 50 candidate iterations. Choose
ridge lambda=1 because the paper does not specify it. Initial evaluation is
additional; duplicate candidates reuse their score. Stable ties keep older
candidates. A conservative splitter preserves formatting; explicit fragment JSON
allows exact mutable boundaries. T5 checkpoint is configurable because the exact
paper checkpoint is unspecified. No benchmark performance claim follows from
the canned demo. Run inline in this non-git workspace; leave sibling projects alone.

Validation: `optimizer/.venv/bin/python apex/test_apex.py`; five-iteration demo;
CLI artifact/call-count/overwrite checks; Ruff lint and formatting checks.
Independent review found and verified fixes for newline normalization on input
and closing mutation tags. T5 weights and real providers were not invoked.
