# LLM_GP implementation plan

**Goal:** Implement the supplied Hemberg, Moskal and O'Reilly paper as a runnable
Slick project, including its two demonstrated LLM variants and three baselines.

**Architecture:** `llm_gp/core.py` owns constrained arithmetic evaluation, tree GP,
data splits and evolution. `operators.py` uses Slick decorated prompt functions,
response validation, retries and call accounting. `run.py` owns the CLI and saved
experiment artifacts. Only Slick and its existing Pydantic dependency are needed;
the OpenAI SDK is optional for live API calls.

**Source:** User-supplied paper, sections 3 and 5, Tables 3–4, Appendices 2–3.
The authors' repository is https://github.com/ALFA-group/Tutorial_GP-LLM.

## Design decisions

- Implement the executable demonstration: numeric local fitness, not hypothetical
  LLM arithmetic. Include LLM initialization, mutation, crossover, selection,
  replacement and best designation with the formulate/interface/check sequence.
- Use text genotypes for LLM variants; trees only for traditional GP variation.
- Use a bounded AST interpreter for `+ - * x0 x1 0 1`; never execute Python output.
- Fix pseudocode population overshoot and final unevaluated offspring: generations
  mean evaluated populations, including initialization, so FE = population × generations.
- Keep raw prompts/responses, errors/fallbacks, durations, fitness and size history,
  data splits, seeds and explicit provider/model metadata. Unknown usage/cost is null.
- Demonstrate all paths offline with labeled canned responses. Live API models
  are explicit CLI input. No historical replication or model-discovery claims.

## Validation results

- Integration check passes through real Slick rendering/parsing and a scripted
  transport, including invalid expressions/IDs, retry exhaustion, timeouts,
  SDK usage capture, cost calculation, and model designation versus measured best.
- Twenty offline runs completed: all five variants, two seeds each, at both
  300 and 1,200 FEs. Saved JSON, population sizes, call counts and aggregate
  summaries were independently checked. Invalid CLI settings and overwrite
  attempts return exit code 2.
- Independent code review found no execution/security defects; its training-size
  concern is explicitly addressed by the README's data/fidelity section.
- Ruff passes. No live model calls or published-result replication were performed.
- A project-local virtual environment was installed from the existing offline
  cache with editable Slick pointing at `/Users/stuart/Developer/AI/slick`.
