# EoH implementation plan

**Goal:** Implement the supplied ICML 2024 EoH algorithm using the local Slick checkout.
**Architecture:** A standalone `eoh/` example, with Slick typed proposal prompts,
an ordinary Python evolutionary loop, NumPy problem evaluators, and a subprocess
worker. No changes to Slick or the existing examples.
**Specification:** User-supplied paper, sections 3–4 and appendices B–D.
**Dependencies:** Python 3.10+, local Slick, NumPy; stdlib test runner.

- [x] Write `eoh/test_eoh.py`: exact generation budgets and elitism using a canned
  provider, feasibility on known small instances, invalid proposals and timeouts.
  Run with `optimizer/.venv/bin/python eoh/test_eoh.py` before implementation.
- [x] Implement `eoh/problems.py`: online bin packing with feasible open bins and
  argmax scores; TSP GLS with 2-opt/relocate; permutation flow shop GLS with
  swap/relocate and selected perturbation jobs. Validate matrices and returned
  values, protect original objectives from candidate input mutation, and retain
  best feasible solutions under the original objective.
- [x] Implement `eoh/evolve.py`: thought/code/fitness representation, initialization,
  all five prompts, sampling proportional to `1/(rank + N)` with one-based ranks,
  distinct exploration parents, a fixed parent population per generation, and
  top-N survival. Log proposals, failures, populations and best code. Bound initial
  retries; each evolutionary attempt consumes one slot, including invalid output.
- [x] Implement `eoh/worker.py`: syntax/interface checks and process deadline for
  each candidate evaluation. This is trusted Python execution, not a sandbox.
- [x] Add CLI, offline provider, smoke/paper presets, JSON datasets, baseline
  evaluation and ablation operator choices. Use negative minimization objectives
  internally so every search fitness is maximized. TSP gaps require optima.
- [x] Document setup, execution, interfaces and reproducibility differences in
  `eoh/README.md`; link from root README. Run local checks and all three offline
  end-to-end demos. Do not run a paid search or claim reproduction of paper results.

The supplied paper authorizes implementation; execute inline without a separate
approval round. This workspace is not a Git repository, so no worktree or commits.
